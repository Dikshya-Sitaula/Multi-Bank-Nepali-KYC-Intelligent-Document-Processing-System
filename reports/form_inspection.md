# Visual inspection of the blank source forms

Written during Phase 1 after viewing every page of each PDF. This records what is actually
on the forms, so later template enrollment does not rely on the quick notes in SPEC §5.
Numeric quality measurements are in `reports/source_quality.md` (generated by code).

## `nicasia` — NIC_ASIA_KYC_Update_Individual.pdf (5 pages)

Brand on the form is **NIC ASIA CAPITAL** (KYC update form, "Details of Natural Person").
Matches the SPEC notes. Observations that differ from or add to the notes:

- **Printed prefill:** DP ID cells are pre-printed `1 3 0 1 3 7 0 0`. Must be
  `printed_prefill: true`; the generator must not write there and YOLO must not learn it as
  handwriting. Client ID cells (8) are blank.
- A large faint red star watermark sits behind every page. Thresholding and checkbox
  fill-ratio must tolerate it.
- Page 1: date, branch, name in two rows of block-letter cells, DOB B.S. and A.D. cells,
  PAN box, nationality checkboxes (Nepali / Other), gender checkboxes (Male / Female / Other),
  citizenship no / issue district / issue-date cells, email, NRN ID and address, national ID,
  married yes/no, 16-row family table (odd rows Nepali name free text, even rows English
  block-letter cells), "Recent Photo" box top right.
- Page 2: current address (country, province, district, municipality, ward, tole, block,
  telephone, mobile, alternate mobile), permanent address (same plus nearest landmark),
  bank account details (4 rows), occupation (12 checkboxes), business type (3), organisation
  name and address, designation, employee ID, income range (5 checkboxes).
- Page 3: guardian details (minor only) repeating name cells, citizenship, address,
  occupation and income blocks; guardian photo, guardian thumbprints right/left, guardian
  signature; NRN section (foreign address, city, state, country, NRN code), a second
  thumbprint pair and guardian signature.
- Page 4: location map box, "From Main Road Street ... distance ... Meters" dotted lines,
  customer thumb impression right/left, customer signature, office-use block.
- Page 5: Nepali self-declaration with 10 छ/छैन (yes/no) box pairs, two PEP detail tables,
  investment-company role checkboxes, beneficial-owner table, account-holder name and
  signature on dotted lines, office-use block.

## `laxmisunrise` — Laxmisunrisebank-Individuals.pdf (4 pages)

Clean vector PDF, orange theme. The PDF has a text layer but **Devanagari extracts as
Preeti-encoded garbage** (e.g. "gfd y/" for नाम थर), confirming that text layers must not
be used. Matches SPEC notes; additions:

- Page 1: branch on dotted line, photo box, name line, DOB B.S. and A.D. cells, sex
  checkboxes, nationality and country lines, 3-column address table with 9 rows (house no,
  tole, ward, municipality, district, province, tel, mobile, email), citizenship table,
  NID 12 cells plus "haven't received" checkbox, passport table, PAN 9 cells plus
  "haven't received" checkbox, other-ID table, minor birth-certificate table, guardian ID
  table, education line.
- Page 2: family table (spouse, father, mother, grandfather, 3 sons, 3 daughters,
  3 daughters-in-law, father-in-law = 14 name rows), source-of-income checkboxes (5) with two
  specify lines, 3-row occupation table (6 columns), annual transaction line, five yes/no
  questions (12-16), crime detail line, existing account number cells.
- Page 3: other-BFI yes/no and 4-row bank table, foreign national yes/no + 4 status
  checkboxes + 7 detail lines, landlord name/address/contact, large location-map box with
  nearest landmark and distance lines.
- Page 4: declaration text, right/left thumbprint boxes, account-holder signature line, date.
  The printed footer on this page reads "8", not "4"; the page order in the PDF is still 1-4.

## `nabil` — nabil_kyc.pdf (8 pages)

Green theme, account opening form (individual-joint). Visibly **low quality**: JPEG
artefacts, soft text, light grey placeholder text in cells. Matches SPEC notes; additions:

- Page 1: account no cells (bank use), date cells, account type and currency checkboxes,
  account holder names, purpose, source of funds, existing account cells; **Joint
  Applicant 1** identity block (title, name cells, gender, marital, nationality, DOB
  B.S./A.D. cells, education, parents/grandparents/spouse names, family size, permanent,
  current and office address lines, contact lines).
- Page 2: applicant 1 non-resident contact, landlord, ID document checkboxes and lines,
  PAN, 7-row family table, occupation (salaried, self-employed, additional), other bank.
- Page 3: applicant 1 location map with landmark/distance, KYC declaration lines, 4-row PEP
  table, three yes/no questions.
- Page 4: **Joint Applicant 2** identity block (same fields as page 1 second half and page 2
  first half). `applicant_index` must come from the template page, not from YOLO.
- Page 5: applicant 2 family table, occupation, other bank, location map.
- Page 6: applicant 2 KYC declaration, transaction info, services checkboxes.
- Page 7: online/mobile banking checkboxes, specimen signature, right/left thumbs and photo
  for **both** applicants.
- Page 8: introducer, enclosed-documents checkboxes, applicants' signature, bank-use block.

Every page has an "Applicants' Signature" line at the bottom right.

## Conclusions for later phases

- Use raster images only; never PDF text.
- Measured triage (`reports/source_quality.md`) agrees with the visual inspection:
  - `nicasia`: embedded JPEG scan at about 144 DPI, no vector drawings. Clean enough for
    training. Region proposal must be raster-based (OpenCV).
  - `laxmisunrise`, `machhapuchhre`: vector PDFs. Clean training templates; vector
    rectangles and lines can drive region proposal.
  - `nabil`: embedded JPEG scan at about 69 DPI, visibly soft. Evaluation only, as the
    held-out unseen-template experiment.
